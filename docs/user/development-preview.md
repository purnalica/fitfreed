# Development Preview Guide

## Important boundary

The current application is a development preview, not an alpha release. It proves source-subject-safe
daily-activity, training summary, structural exercise/lap/pause, primary and transition route, supported interval signal, and supported recorded-zone,
primary-sleep, and dated nightly-recovery import; explainable outcomes; mapping-aware reimport; detailed
domain exploration; complete-history sport discovery with reversible user-authored classification and
reusable personal session segmentation;
complete-history training-session search; and an integrated longitudinal range, day synopsis, navigation,
and comparison journey. Route traces use only local SVG and retain paginated access to every exact recorded
point. Supported signals use gap-aware bounded charts and retain paginated access to every exact source
sample. Recorded heart-rate, speed, and power zones preserve exact source bounds and applicable aggregates;
unsupported zone kinds and signal types remain explicit counts rather than guessed facts. Undated recovery
samples remain deliberately excluded. Sleep exposes missing nights and optional-measurement coverage instead of inventing values.
Recovery keeps shared intervals distinct from source-specific assessment, baseline, and guidance, and makes
no medical interpretation. The longitudinal view aligns recorded co-occurrence without merging sources or
asserting causation.

One supplied reference export has passed private, privacy-minimized activity, training, sleep, dated
nightly-recovery, origin-correlation, coverage, and reimport predicates, but that does not establish broad
historical compatibility. Do not use a real personal export yet: user-controlled backup is unavailable and
the exact public candidate has not passed its privacy, installation, update, and usability gates. Read the project-wide
[disclaimer](../../DISCLAIMER.md) before running any build.

## Run the synthetic journey

The Application updates panel in Settings performs a non-blocking launch check after the language preference is ready, repeats scheduled discovery every 24 hours while FitFreed remains open, and always offers an explicit check. Sleeping or delaying a check cannot create a burst of requests, and a periodic attempt is skipped while another update operation is active. Manual check, installation, candidate dismissal, postponement, and result-dismissal actions keep their names while their surfaces are busy and announce the exact localized operation. The ordinary development build is intentionally unconfigured and makes no update request. A configured build offers installation only for the exact newer compatible release authorized by a fresh authenticated check. Before replacement, FitFreed verifies the package and preserves the current application and library; an independent watchdog then owns restart confirmation or restoration. Installation cannot overlap an import or another update. After a successful update or automatic recovery, the next ready startup shows a localized result with the previous and resulting version. The notice remains until its acknowledgement is stored. Synthetic unit, integration, presentation, and packaged tests exercise this complete boundary. A private channel and production signing authority remain unconfigured, so this is not yet a supported distribution path.

## Troubleshooting this preview

- If the import action is unavailable, select a ZIP package first. Canceling the file picker intentionally keeps the action unavailable.
- The generated `invalid.zip` package is expected to be rejected. Use `valid.zip` for the successful journey and preserve the visible rejection evidence when diagnosing a regression.
- If FitFreed reports that the local library is unavailable, stop importing and preserve the application-data directory. Do not delete or edit the SQLite file as a recovery attempt.
- If application settings cannot be saved, the application keeps the operating-system defaults for first-run initialization or restores the previous complete preference set. Restart before trying the save again. If FitFreed reports that incompatible settings were recovered, review the safe defaults in Settings and save any changes you want to keep.
- If a configured update fails before replacement, the current application remains installed. If failure occurs after replacement begins, wait for bounded automatic recovery and reopen FitFreed if it does not relaunch. A successful replacement or recovery displays a notice that must be acknowledged in the application. If acknowledgement fails, keep the notice and retry; do not delete or edit `update-recovery` or the SQLite library. Preserve the application-data directory when reporting a recovery failure.
- Use the [contributor troubleshooting guide](../development/troubleshooting.md) for build, test, package, or E2E failures.

## Expected limitations

- Only the documented daily-activity, training summary, exercise/lap/pause structure, route, supported interval-signal series, supported recorded-zone groups, split sleep-result, and dated nightly-recovery compatibility matrices are supported; one evaluated package is evidence, not a universal provider guarantee.
- Activity, sleep, recovery, and longitudinal overview and comparison ranges accept at most 366 inclusive dates; their default windows remain bounded. Training-session search spans the complete library through coherent 25-session pages and combinable date, sport, authored-label, and measurement filters. Its chronology, source-separated calendar, comparison basket, structural, route, signal and recorded-zone detail, reusable personal segmentation, and restart restoration remain bound to one coherent discovery snapshot. Sport classifications, segment criteria, report narrative, and report composition are explicit user interpretations of retained source evidence and never invented provider names or source structure. External maps, unsupported provider-defined zone kinds, unsupported signal types, native PDF and spreadsheet reports, and exact-sample report blocks remain outside the current boundary. Sleep scores and recovery assessments remain source-derived facts rather than medical interpretation. Undated recovery samples, user-controlled backup, portable normalized export, and a production update authority are not implemented yet. The machine-readable [0.1.0 release matrix](../../release/upgrade-matrix.json) is the source of truth for direct library compatibility and has no application upgrade baseline because no prior FitFreed release exists.
- The visible coverage is exact for the current recognition boundary and does not expose archive filenames. A recognized or classified family is not necessarily imported, and the view is not a claim that all historical Polar Flow takeouts are fully supported.
- The package is unsigned and must not be published as a public release.

These are open product gates, not accepted permanent behavior.
