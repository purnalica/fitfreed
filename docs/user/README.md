# User Documentation

## Current availability

FitFreed has an executable development preview but no supported alpha release. It is not ready for a real personal export. Current builds demonstrate import safety, source-subject correlation, reconciliation, localized family coverage, and a persisted gap-aware daily overview with independently generated synthetic ZIP packages. One private reference export has passed the privacy-safe compatibility predicate; that evidence does not establish universal compatibility or open the alpha boundary.

The [development preview guide](development-preview.md) is the only current application walkthrough. It identifies the documented compatibility shape, synthetic runnable steps, expected overview results, and missing product capabilities.

The [private development package guide](private-development-packages.md) explains integrity verification and the unsigned evaluation boundary. It does not turn a development package into a supported release.

## Safety boundary

- Read the [project disclaimer](../../DISCLAIMER.md) before running a build.
- Preserve every original provider export outside FitFreed.
- Do not import personal data until an alpha version explicitly documents compatible data, backup, recovery, installation, and update behavior.
- Never attach a real export, local library, route, screenshot, log, or diagnostic bundle containing personal data to a public report.
- Report suspected vulnerabilities through the confidential route in [SECURITY.md](../../SECURITY.md), not through a public issue.

Installation, backup, recovery, update, removal, and real-export compatibility instructions will be published with the first version that implements and verifies those behaviors. Their absence is a product gate, not permission to infer a procedure from development internals.
