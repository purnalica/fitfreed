# SQLite Persistence Schema Version 2

## Status and boundary

Exact implementation specification for local-library schema version 2. It supersedes version 1 for current application writes without changing the separate, future FitFreed portable export contract. SQLite `PRAGMA user_version` stores value 2 after a successful migration.

Version 2 is produced by applying the immutable [`0002_import_ledger.sql`](../../../src-tauri/migrations/0002_import_ledger.sql) migration after [`0001_initial.sql`](../../../src-tauri/migrations/0001_initial.sql). A new library applies both assets in one transaction. An existing version 1 library applies only the second asset. Any error or interruption before commit restores the original schema and `user_version`.

## Compatibility and recovery

- Versions 0 and 1 migrate forward to version 2. Version 2 opens without migration. A later or otherwise unsupported version is rejected without modification.
- Version 1 observations, conflicts, and completed operations are retained. Evidence that version 1 never recorded is marked unavailable; it is not inferred.
- A migrated version 1 operation has incomplete coverage, null timestamps, and `legacy-v1-unknown` adapter and mapping versions.
- A startup recovery pass moves any non-terminal operation through `recovering` to `failed`. Because canonical changes and `completed` are committed in one SQLite transaction, a surviving non-terminal row proves that no partial canonical result became visible.
- Exact byte repeats only use a prior `completed` operation whose coverage is complete. The new operation links to it and copies its artifact evidence without duplicating canonical history.

## Transaction and visibility model

Assessment metadata and artifact coverage are durable while an operation is non-terminal. Canonical observations, detailed provenance, conflicts, reconciliation counts, and the transition from `committing` to `completed` share one visibility transaction. Consumers treat coverage as a final outcome only when its operation is terminal. Cancellation, rejection, failure, or a confirmed transaction rollback exposes no canonical changes.

All timestamps are UTC text generated by SQLite in an ISO 8601 form such as `YYYY-MM-DDTHH:MM:SS.sssZ`. Timestamps are nullable only so migration can preserve the fact that version 1 did not record them.

## `import_operation`

One row is the durable lifecycle and outcome of one import attempt.

| Column | SQLite type | Null | Contract |
|---|---|---|---|
| `id` | INTEGER | no | Internal primary key. |
| `operation_ref` | TEXT | no | Unique opaque local reference; new values are random 128-bit lowercase hexadecimal strings. Migrated values use a non-secret `legacy-v1-` reference. |
| `package_sha256` | TEXT | yes | Lowercase package SHA-256 after fingerprinting; exactly 64 characters when present. |
| `state` | TEXT | no | `assessing`, `planned`, `staging`, `reconciling`, `committing`, `recovering`, `completed`, `rejected`, `cancelled`, or `failed`. |
| `source_provider` | TEXT | no | Provider identifier; current writes use `polar-flow`. |
| `source_adapter_version` | TEXT | no | Adapter contract; current writes use `polar-flow-archive@1`. |
| `mapping_version` | TEXT | no | Mapping contract; current writes use `polar-flow-daily-activity@1`. |
| `started_at_utc` | TEXT | yes | Operation creation time; null only for migrated version 1 history. |
| `updated_at_utc` | TEXT | yes | Last lifecycle update; null only for migrated version 1 history. |
| `completed_at_utc` | TEXT | yes | Terminal transition time; null for non-terminal and migrated version 1 rows. |
| `exact_repeat` | INTEGER | no | Boolean indicating byte-identical evidence reuse. |
| `repeated_operation_id` | INTEGER | yes | Self-referencing foreign key to the completed operation whose evidence was reused. |
| `coverage_complete` | INTEGER | no | Boolean; true only when every inventoried artifact has one coverage row. Migrated version 1 rows remain false. |
| `total_artifacts` | INTEGER | no | Non-negative safe ZIP-member inventory count. |
| `supported_artifacts` | INTEGER | no | Non-negative `supported` coverage count. |
| `unsupported_artifacts` | INTEGER | no | Non-negative `unsupported` coverage count. |
| `ignored_artifacts` | INTEGER | no | Non-negative `deliberately-ignored` coverage count. |
| `unrecognized_artifacts` | INTEGER | no | Non-negative `unrecognized` coverage count. |
| `invalid_artifacts` | INTEGER | no | Non-negative `invalid` coverage count. |
| `recognized_artifacts` | INTEGER | no | Non-negative total of supported and invalid recognized-family artifacts. |
| `new_observations` | INTEGER | no | Non-negative create-decision count. |
| `equivalent_observations` | INTEGER | no | Non-negative equivalent-decision count. |
| `enriched_observations` | INTEGER | no | Non-negative enrichment-decision count. |
| `preserved_observations` | INTEGER | no | Non-negative preservation-decision count. |
| `conflicts` | INTEGER | no | Non-negative conflict-decision count. |

| `recovery_note` | TEXT | yes | Stable sanitized recovery result; startup rollback recovery uses `canonical-transaction-rolled-back`. |

`import_operation_completed_package` indexes package fingerprint, state, and coverage completeness for the exact-repeat lookup.

## `import_artifact_coverage`

A completed assessment gives every inventoried safe member exactly one row. Cancellation or system failure may leave a documented prefix; `coverage_complete` remains false in that case.

| Column | SQLite type | Null | Contract |
|---|---|---|---|
| `id` | INTEGER | no | Primary key. |
| `import_operation_id` | INTEGER | no | Foreign key to `import_operation`. |
| `artifact_locator` | TEXT | no | ZIP-root member name. It is protected local-library data and is not included in public diagnostics. |
| `artifact_family` | TEXT | yes | Recognized adapter family; null when no family is known. |
| `classification` | TEXT | no | `supported`, `unsupported`, `deliberately-ignored`, `unrecognized`, or `invalid`. |
| `source_artifact_sha256` | TEXT | yes | SHA-256 of expanded artifact bytes; exactly 64 characters when mapping read the artifact. |
| `reason_code` | TEXT | no | Stable classification reason without source values. |

The (`import_operation_id`, `artifact_locator`) pair is unique. `import_artifact_coverage_operation` indexes operation and classification.

## `daily_activity`

| Column | SQLite type | Null | Contract |
|---|---|---|---|
| `origin_id` | TEXT | no | Canonical `originId`; first part of the primary key. |
| `local_date` | TEXT | no | Canonical `localDate`; second part of the primary key. |
| `step_count` | INTEGER | yes | Canonical `stepCount`; negative values are rejected. |

The composite (`origin_id`, `local_date`) key remains the provider-neutral logical identity. Package evidence moved out of this table because one observation can have multiple provenances.

`daily_activity_provenance_observation` indexes canonical identity and operation. Provenance rows are part of the protected personal library even when they contain no raw source value.

## Implemented terminal codes

Version 2 can persist `user-cancelled`, `invalid-zip-container`, `invalid-supported-artifact`, `unsafe-archive-member`, `duplicate-archive-member`, `archive-resource-limit`, `archive-io-failure`, `database-failure`, `invalid-operation-transition`, and `interrupted`. Codes describe the category only; detailed error text remains transient and must not place personal values in logs or diagnostics.

## Verification evidence

Domain tests enforce lifecycle transition and terminal-state rules. Adapter integration tests cover clean creation, version 1 migration, migration rollback, complete mixed coverage, detailed provenance for every reconciliation decision, exact-repeat evidence linking, rejection, cancellation, injected interruption, startup recovery, future-schema rejection, backup, and canonical queryability in [`../../../src-tauri/src/infrastructure.rs`](../../../src-tauri/src/infrastructure.rs).

## Known version 2 limitations

Version 2 does not yet resolve a stable real Polar subject identity, retain original artifacts, expose warnings as a separate collection, persist resumable staging batches, or provide the stable portable FitFreed export. The current provider adapter recognizes only the independently constructed daily-activity slice documented by mapping version 1. The presentation reads terminal outcome summaries and recovery codes through a provider-neutral application port; detailed artifact locators and provenance remain protected local-library evidence.
